# Speech-M Core Execution Skill

## 목적
Speech-M 프로젝트에서 반복되는 고위험 작업(크롤링, AI 필터링, RLS, Next.js 호환성)을 일관된 절차로 수행한다.

## 사용 트리거
- 크롤링/수집/배치/스케줄 변경 요청이 들어온 경우
- Supabase 스키마/정책/접근권한 변경 요청이 들어온 경우
- App Router, Route Handler, Server Action 등 Next.js 핵심 동작을 건드리는 경우
- 관리자 대시보드의 정보 밀도/운영 효율 UI 개선 요청이 들어온 경우
- AI 필터링 기준이 불명확하거나 상세 기준이 누락된 경우

## 실행 절차
1. 작업 분류
   - 아래 4개 체크리스트 중 해당되는 항목을 먼저 식별한다.
2. 체크리스트 적용
   - 해당 체크리스트를 우선 적용하고, 충돌 시 보안/안정성을 우선한다.
3. 검증
   - 최소한 lint/타입/핵심 시나리오 검증 결과를 남긴다.
4. 결과 보고
   - 변경 이유, 트레이드오프, 검증 결과를 간결하게 기록한다.
5. 기준 미정 항목 확인
   - AI 필터링 상세 기준이 비어 있으면 plan 단계에서 먼저 질의하고 확정 후 구현한다.

## 체크리스트 A: 크롤링/배치
- 서버리스 타임아웃(15~60s) 회피 구조인지 확인한다.
- 재시도 가능(idempotent)한 작업 단위인지 확인한다.
- 중복 수집 방지 키가 있는지 확인한다.
- 실패 시 재처리 경로(큐/스케줄/수동 트리거)가 있는지 확인한다.

## 체크리스트 B: AI 필터링
- 타깃 직군/기관 기준이 도메인 정책과 일치하는지 확인한다.
- 제외 규칙(취재기자/유튜브 전용/소형 에이전시)이 유지되는지 확인한다.
- 모델 선택/프롬프트 변경 시 회귀 비교 기준(golden set)이 있는지 확인한다.
- HITL 정책(명확 합/불합 자동 처리, 애매 케이스 관리자 검토)이 반영되는지 확인한다.

## 체크리스트 C: 보안/RLS
- 민감 데이터(시험 후기/학생 데이터)는 기본 비공개 원칙을 유지한다.
- RLS 정책이 테이블 용도와 역할 권한을 정확히 반영하는지 확인한다.
- 서비스 롤 키 사용 경로가 최소 권한 원칙을 지키는지 확인한다.

## 체크리스트 D: Next.js 호환성
- 프레임워크 관련 결정은 `node_modules/next/dist/docs/` 기준으로 검증한다.
- 구버전 관습을 그대로 쓰지 않는지 확인한다.
- 경고/디프리케이션 메시지를 우선 해결한다.

## 체크리스트 E: 확장 모듈(대본/스터디/CRM)
- 대본 수집/문서화/발송 작업은 배치 처리와 실패 재시도 경로를 갖는지 확인한다.
- ZIP 번들링/출석·보증금 계산 로직은 데이터 무결성 검증 단계를 포함하는지 확인한다.
- 프라이빗 CRM 데이터는 보관 기간/삭제 정책을 명시적으로 따른다.

## 출력 형식

- 핵심 근거 3개 이내
- 다음 액션(검증 또는 배포 전 확인사항)
